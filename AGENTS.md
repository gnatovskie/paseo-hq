# Инструкция для AI-агентов: Штаб Paseo (Paseo HQ)

Этот документ предназначен для AI-ассистентов (Claude, Codex, Antigravity, Cursor и других), работающих в проектах с установленным плагином **Paseo HQ (Штаб)**. Здесь описано, как устроен плагин, как правильно оформлять артефакты в чате и как помогать пользователю настраивать окружение.

---

## 1. Архитектура и возможности плагина

Плагин **Paseo HQ** превращает рабочий стол Paseo в единый командный центр:
- **Проекты, области и сессии («Штаб»)**. Области группируются по проектам, получают короткие названия и могут переноситься между проектами.
- **Интерактивные артефакты**: автоматическое распознавание HTML, SVG и Markdown в чате, превращение их в интерактивные карточки с песочницей, скачиванием, просмотром во весь экран и доставкой в Telegram.
- **Галерея артефактов (`/surface/artifacts`)**: единая библиотека созданных документов с фильтрами по проектам, типам и поиском, а также возможностью удаления ненужных карточек.
- **Монитор воркеров (Workers)**: мониторинг контейнеров (LXC / Docker) и окружений разработчиков/агентов через cgroup v2.
- **Системные службы (Host Services)**: мониторинг состояния systemd-сервисов хоста без прав root.
- **Учет расходов моделей (Usage)**: отслеживание токенов и лимитов провайдеров.

## 2. Как агенту генерировать артефакты

Когда вы создаете для пользователя дашборд, схему, интерактивный калькулятор или документ, оформляйте их так, чтобы Штаб распознал их как интерактивные артефакты.

### HTML-артефакты (дашборды, отчеты, веб-страницы)
Используйте блок ````html` с указанием `filename`:

````html filename="report.html"
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8" />
  <title>Финансовый отчет Q3</title>
  <style>
    body { font-family: system-ui, sans-serif; padding: 20px; background: #0f172a; color: #f8fafc; }
    .card { background: #1e293b; padding: 16px; border-radius: 8px; margin-bottom: 12px; }
  </style>
</head>
<body>
  <h1>Финансовый отчет Q3</h1>
  <div class="card">
    <p>Выручка: +24%</p>
  </div>
</body>
</html>
````

**Что происходит в интерфейсе:**
1. Штаб автоматически превращает блок в интерактивную карточку в ленте сообщений.
2. Пользователь может нажать **«В новой вкладке»** для открытия на весь экран или **«Скачать»**.
3. Если настроен Telegram-бот, HTML-артефакт автоматически прилетает в Telegram пользователя, где его можно мгновенно открыть с телефона во встроенном Safari.

### SVG-артефакты (архитектурные схемы, диаграммы)
Используйте блок ````svg` с указанием `filename`:

````svg filename="network-topology.svg"
<svg viewBox="0 0 400 200" xmlns="http://www.w3.org/2000/svg">
  <title>Схема сети</title>
  <rect width="100%" height="100%" fill="#18181b"/>
  <circle cx="100" cy="100" r="40" fill="#3b82f6"/>
  <circle cx="300" cy="100" r="40" fill="#10b981"/>
  <line x1="140" y1="100" x2="260" y2="100" stroke="#71717a" stroke-width="2"/>
  <text x="100" y="105" fill="#ffffff" text-anchor="middle" font-size="12">Frontend</text>
  <text x="300" y="105" fill="#ffffff" text-anchor="middle" font-size="12">Backend</text>
</svg>
````

### Markdown-документы (планы, спецификации, брифы)
Чтобы блок Markdown превратился в карточку артефакта, явно укажите атрибут `filename="...md"` или тег `artifact:markdown`:

````markdown filename="architecture-plan.md"
# Архитектурный план сервиса

1. Микросервис аутентификации на Go.
2. База данных PostgreSQL 16.
3. Очередь задач RabbitMQ.
````

> **Важно:** Обычные текстовые рассуждения, списки задач и фрагменты кода в чате без тега `filename="...md"` **НЕ** становятся артефактами. Это сделано специально, чтобы лента чата не засорялась карточками.

### Сохранение файлов на диск проекта
Если агент генерирует файлы на диске, сохраняйте артефакты в подкаталог `artifacts/` корня репозитория (например, `my-project/artifacts/summary.html`).
Штаб автоматически обнаруживает файлы в каталоге `artifacts/` после завершения хода агента и регистрирует их в галерее. Файлы в корне проекта (`README.md`, `package.json`, `.env`) игнорируются сканером, чтобы библиотека оставалась чистой.

## 3. Взаимодействие агентов и ссылки

Все окна Штаба (HqModal в index.client.tsx) рисуются самим плагином внутри одной модалки HqModalLayer, а не модалками хоста: так их внешний вид можно менять, окна открываются друг поверх друга без борьбы за фокус, Escape закрывает верхнее.

В Штабе проект содержит области (workspace в Paseo). Сессия - это вкладка области. Сессии бывают двух видов: агенты с перепиской и терминалы. У агента есть идентификатор `agentId` (UUID).

### Формат ссылок на агентов
- **Нативный Deep Link**: `paseo:///h/<serverId>/agent/<agentId>` (например, `paseo:///h/local/agent/073a4a42-1c2f-4516-aa2c-1bf26869bbe2`). По клику открывает приложение Paseo прямо на нужной вкладке.
- **Web URL**: `https://<host>/h/<serverId>/agent/<agentId>`.
- **Короткий или полный ID**: `073a4a4` или `073a4a42-1c2f-4516-aa2c-1bf26869bbe2`.

Окна «Новая область» и «Новая сессия» собраны из одного компонента NewSessionWindow и отличаются только полем названия области: переключатель «Агент» или «Терминал» рядом иконок под названием, выбор модели у агента, папка у терминала, кнопка создания. В окне «Новая область» сверху есть выбор «Область»: новая область или одна из уже имеющихся в этом проекте (у имеющейся справа бейдж с ее веткой). Для имеющейся поле названия скрыто, кнопки создают агента или терминал в ней, а папка терминала берется у выбранной области. Менять оба окна надо вместе, в одном месте.

В git-проектах в «Новой области» есть блок «Ветка»: «В папке проекта» (как раньше), «Существующая ветка» или «Новая ветка» от выбранной базовой. Для двух последних Штаб сам создает worktree командой git worktree add: по умолчанию папка рядом с проектом, `<родитель>/<проект>-<ветка>` (например `repos/paseo-hq-feature-x`), путь можно поправить. Область открывается из этой папки как обычная область того же проекта (проверено: Paseo принимает папку вне корня). Ветку, уже открытую в другой папке, взять нельзя. Paseo такие папки при архивации не удаляет, поэтому Штаб спрашивает: удалить папку, оставить, а при незакоммиченных изменениях показывает их и удаляет только с явным подтверждением. Бейдж с веткой стоит под названием области вместо индикаторов статусов, когда область раскрыта (у свернутой видны индикаторы), и показывается у любой git-области, не только у worktree Штаба: ветку определяет сервер через git. Путь worktree виден в «Действиях области». Код: server/area-worktree.server.ts. В одной области разные ветки для разных агентов держать нельзя: у всех общая рабочая папка, ветка на область одна.

В сайдбаре нажатие на область раскрывает ее сессии: список лежит во вдавленной рамке без акцентной полоски, ее левый край на одной вертикали с названием области, чтобы длинный список не сливался со следующей областью. Снимок провайдеров кэшируется (shared/provider-cache.ts): ключ - корень проекта, а не папка каждой области, срок 10 минут, одновременные запросы объединяются, при ошибке «модель недоступна» кэш сбрасывается: так открытие окон не опрашивает провайдеров каждый раз и не упирается в лимиты. Модель нового агента берется у последней сессии проекта из уже загруженных данных сразу, а полный список моделей провайдеров грузится в фоне и нужен только для выбора из него. Плюс у проекта открывает форму новой области с начальным названием «Новая область» и выбором первой вкладки. В строке свернутой области под названием видны счетчики с индикаторами запущенных, готовых, неактивных сессий, ожидания ввода и ошибок. Перед кнопкой действий области стоит шеврон: вправо у свернутой, вниз у раскрытой. Он и нажатие на название раскрывают и сворачивают область (aria-expanded сохранен). Нулевые счетчики скрыты, терминалы учитываются как неактивные сессии. В раскрытой области под названием слева стоит акцентная кнопка с плюсом и иконкой агента, справа от нее нейтральный бейдж Git. Размеры кнопки как у бейджа ветки и счетчиков свернутой области: высота 20, горизонтальные отступы 6, радиус 6. Кнопка открывает общую форму создания агента или терминала в этой области и не сворачивает список. У папки без Git остается только кнопка, бейджа ветки нет.

Иконка с четырьмя плитками открывает «Действия области» (окно всегда фиксированной высоты, длина списка сессий её не меняет): окно Штаба: название и крупный крестик в одной строке, ряд иконок-действий под ними. Название редактируется прямо в поле и сохраняется при потере фокуса. Пока поле активно, кнопка генерации заменяется галочкой «Принять название» (то же в меню агента и терминала). Клик вне окна остается запасным способом сохранить, одна правка сохраняется один раз. Эмодзи можно вписать в название. Кнопка генерации предлагает название по верхнему агенту, используя глобальную модель Штаба. Под названием области показаны ветка, тип папки и путь с копированием. Настройка смены ветки удалена. Плюс стоит в углу блока «Сессии» и открывает окно «Новая сессия», оно уже действий области (все окна поверх других окон уже родительских, 400 вместо 520 пикселей): переключатель «Агент» или «Терминал» рядом иконок под названием, у агента выбор модели перед созданием, у терминала информационная строка с папкой, в которой он будет создан, и кнопка создания. При создании области с первым агентом модель также выбирается в форме до создания. В обоих окнах есть отдельное необязательное название агента или терминала: в поле можно нажать напрямую, рядом всегда кнопка редактирования, которая ставит фокус и каретку в конец названия. Генерации названия при создании нет. Имя передается в создание сразу. Проверка без платных вызовов: `PASEO_CHROMIUM_EXECUTABLE=<путь к Chromium> node --test tests/session-settings/creation-names.mjs`.

В раскрытом проекте разделы «Области» и «Пулы». Пулы пока показывают заглушку готовящегося сервиса, создавать их нельзя. Сводка проекта показывает число областей и ноль пулов.

Настройки проекта открываются в таком же окне Штаба. Слева от поля названия стоит кнопка с иконкой проекта: пока картинка не выбрана, на ней первые буквы первых двух слов названия. Кнопка открывает окно «Иконка проекта» (загрузка файла, ссылка или путь, значок и цвет фона, кнопка «Применить»). Папка проекта показана в информационном блоке как в действиях сессии. Название сохраняется при потере фокуса или по галочке, закрепление и скрытие сохраняются сразу, ряд иконок под названием окна: закрепить, скрыть, убрать проект из списка (второе нажатие подтверждает).

Раздел «Сессии» показывает открытых агентов и терминалы области. Список вкладок с файлами и браузером хранится в клиенте Paseo и через SDK плагина недоступен. Фильтры «Все», «Агенты», «Терминалы» и «Закрытые» (с числом закрытых агентов) меняют состав списка. Нажатие на строку открывает вкладку. В списке сессий окна действий области шевроны перехода не показываются, включая закрытых агентов. Меню агента в панели и в сайдбаре позволяет править название в поле (сохраняется при потере фокуса, рядом генерация с глобальной моделью Штаба), закрепить агента наверху списка, перезагрузить или закрыть агента. Закрепленные агенты и терминалы идут первыми в порядке закрепления и не двигаются от активности. Под названием терминала видна его рабочая папка при создании. В окне действий агента под названием показаны текущие провайдер и модель, ссылка на агента с отображением ID, текущая ветка и рабочая папка агента с кнопками копирования (кнопка у ID копирует ссылку). У терминала в том же инфоблоке показаны текущая ветка и папка терминала. При открытии меню данные обновляются, для папки без Git ветка не показывается. В его меню можно переименовать терминал в поле (имя хранится в Штабе, SDK плагина не умеет менять имя в Paseo; пустое имя возвращает исходное), закрепить, скопировать этот путь или закрыть терминал с подтверждением.

Фильтр «Закрытые» показывает архивных агентов текущей области. Открытие агента из этого списка показывает переписку в архиве. Возврат в работу выполняется отдельной кнопкой разархивации в чате. Paseo удаляет запись терминала при закрытии. Архивация области завершает ее терминалы и может удалить ее выделенный worktree вместе с незакоммиченными файлами.

У всех сессий области общая рабочая папка Git. Новые агенты используют текущую ветку общей папки без проверки старой настройки ветки по умолчанию. Бейдж в списке показывает ветку в момент запуска агента, если Штаб ее записал.

### Как изучить переписку агента по переданной ссылке
Когда пользователь просит:
> *«Посмотри, что обсуждали с агентом paseo:///h/local/agent/073a4a42-1c2f-4516-aa2c-1bf26869bbe2»*

1. Извлеките `agentId` из ссылки (или используйте утилиту `paseo-chat`, которая сделает это автоматически).
2. Запустите чтение истории через bash:
   ```bash
   # Прочитать последние 20 сообщений
   paseo-chat read "paseo:///h/local/agent/073a4a42-1c2f-4516-aa2c-1bf26869bbe2" --tail 20

   # Или прочитать полную курированную историю
   paseo-chat read <agentId>
   ```
   Либо штатной командой Paseo: `paseo agent logs <agentId>`.
3. Изучите полученный транскрипт и выполните задачу пользователя.

### Как отправить сообщение или задачу другому агенту
Если вам нужно отправить результат или поручение другому агенту:
```bash
paseo-chat send <agent-id-or-url> "Привет! Я проверил ветку, тесты проходят. Можешь продолжать деплой."
```
Либо штатной командой:
```bash
paseo agent send --behavior steer <agentId> "Текст сообщения"
```
**Важно:** Paseo автоматически определяет отправителя через переменную окружения `PASEO_AGENT_ID`. Агент получит сообщение в мягком режиме `steer` (без прерывания текущих операций) с пометкой, от какого агента оно пришло.

### Список доступных агентов
```bash
paseo-chat ls
```
Показывает активных агентов, их статус (idle/running), рабочий каталог и тему.

## 4. Удаление артефактов и безопасность данных

- Пользователь может удалить любой артефакт в Галерее артефактов (`/surface/artifacts`):
  - По клику на иконку корзины на карточке в списке.
  - По кнопке «Удалить» в режиме полноэкранного просмотра.
- При удалении артефакт удаляется из локальной галереи (`~/.paseo/artifacts/`), но если артефакт ранее был выгружен в облако (Яндекс Диск или S3), **внешняя копия в облаке не удаляется**.

## 5. Настройка доставки в Telegram

Для автоматической отправки HTML-страниц и ручной отправки любых артефактов пользователю в Telegram:

1. Создайте файл `~/.paseo/telegram.env` со следующими переменными:
   ```env
   TELEGRAM_BOT_TOKEN="123456789:ABCdefGHIjklMNOpqrsTUVwxyz"
   TELEGRAM_CHAT_ID="987654321"
   ```
   Либо задайте переменные окружения в `~/.bashrc`:
   ```bash
   export TELEGRAM_BOT_TOKEN="123456789:ABCdefGHIjklMNOpqrsTUVwxyz"
   export TELEGRAM_CHAT_ID="987654321"
   ```

2. После перезапуска плагина (`paseo plugin reload paseo-hq`):
   - Все новые HTML-документы из чата будут автоматически отправляться в диалог с ботом.
   - В каждой карточке артефакта появится кнопка **«В Telegram»**.

## 6. Настройка монитора воркеров (`~/.paseo/workers.json`)

Если вы используете изолированные контейнеры (LXC, Docker) или отдельные рабочие окружения для агентов, создайте файл `~/.paseo/workers.json`:

```json
[
  {
    "id": "agent-1",
    "name": "Frontend Agent",
    "avatar": "🧑‍💻",
    "role": "React / Next.js",
    "container": "frontend-box",
    "user": "agent",
    "cgroupPath": "/sys/fs/cgroup/lxc.payload.frontend-box"
  },
  {
    "id": "agent-2",
    "name": "Backend Agent",
    "avatar": "👨‍💻",
    "role": "Go / PostgreSQL",
    "container": "backend-box",
    "user": "agent",
    "cgroupPath": "/sys/fs/cgroup/system.slice/docker-backend.scope"
  }
]
```

Штаб читает стандартный cgroup v2 интерфейс (`cpu.stat`, `cpu.max`, `memory.current`, `pids.current`) и в реальном времени отображает загрузку ядер процессора, потребление памяти и активность воркеров в шапке панели.

## 7. Настройка системных служб (`~/.paseo/services.json`)

Для отслеживания ключевых systemd-служб сервера создайте файл `~/.paseo/services.json`:

```json
{
```

## 8. Команды управления плагином

Если пользователь просит вас настроить, обновить или проверить плагин:

```bash
# Установка и активация
paseo plugin add /path/to/paseo-hq

# Проверка списка активных плагинов
paseo plugin ls

# Перезапуск плагина после изменений в коде или настройках
paseo plugin reload paseo-hq

# Логи плагина
paseo plugin logs paseo-hq

npm --prefix /path/to/paseo-hq run typecheck
npm --prefix /path/to/paseo-hq test
```

## 9. Google AI Pro, Gemini API и живые квоты

По вопросам подключения Gemini API, квот, Pro-кредитов и биллинга сначала
вызовите инструмент hq_gemini_help, если он доступен. Он возвращает каноническую
справку и текущую конфигурацию выбранного хоста без секретов. Тот же текст в
[docs/gemini-api.md](docs/gemini-api.md) и в карточке «Как подключить».
Не путайте подписку Pro с пулом API, ограничения с расходом, снимок с живыми
данными. Конкретные Project ID хранятся только на хосте в gemini-api.json,
не в общей инструкции. Наличие ключа не доказывает доступ OAuth/IAM.
Не включайте биллинг и не покупайте кредиты без поручения владельца.

В действиях агента под информационным блоком отдельная кнопка «Открыть чат» закрывает меню и родительское окно области и переходит к выбранному агенту.

Модель автогенерации названий задается один раз в настройках панели Штаба. Автоматическое именование сессий и кнопки генерации используют ее на всех уровнях. Локального выбора модели у области или агента нет. По умолчанию используется первая строка без ИИ.

Настройки панели используют общий HqModal: поле названия по общему паттерну создания сессии: карандаш справа ставит фокус и каретку в конец, сохранение при потере фокуса, обновление в ряду действий, компактные блоки модели и мониторинга. Модель выбирается нашим TitleModelPicker внутри окна, без системного SettingsSelect поверх HqModal.

Акцентная рамка сессии в действиях области следует выбранной вкладке агента или терминала основной панели. Публичный SDK не передает активную вкладку: веб и Electron читают выбранную вкладку из DOM панели Paseo. При разделенном экране используется выбранная вкладка последней панели, получившей pointerdown или focusin. Сайдбар и окна Штаба сохраняют этот выбор. Если панель еще не определена и выбор неоднозначен, рамки нет. Первый агент не используется как замена.

В раскрытом списке области сайдбара активная вкладка агента или терминала выделена светлым названием с начертанием 600 и легкой подложкой surface1. Неактивные названия приглушены. Размеры и отступы строк сохраняются.

В новой области переключатель первой сессии «Агент / Терминал» находится после настроек ветки и перед названием агента или терминала. В окне «Новая сессия» переключатель остается под шапкой.

Сессии внутри области в сайдбаре и окне действий сортируются по последнему сообщению человека. Ответы, действия инструментов и переименование агента порядок не меняют. У агента без сообщений используется дата создания, при равных датах порядок стабилен по ID. Закрепленные сессии сохраняют приоритет и порядок закрепления, терминалы остаются после незакрепленных агентов. Проверка: `node --test shared/area-agents.test.mjs`, браузер: `PASEO_CHROMIUM_EXECUTABLE=<путь> node --test tests/session-settings/prompt-order.mjs`.

При создании агента в обеих общих формах доступны permissions из modes выбранного провайдера и уровень рассуждения из thinkingOptions выбранной модели. Совместимые настройки наследуются от последнего агента проекта, несовместимые заменяются объявленными значениями по умолчанию. Настройки показаны компактными выпадающими селекторами, не развернутыми списками и не текстовыми полями для ID. Поведение и проверка: docs/agent-creation.md.

Поле названия нового агента изначально пустое. «Агент без названия» - запасная подпись для сессии без названия до начала диалога, она не передается как явное имя при создании. У терминала в поле подставляется `Terminal N` по числу открытых терминалов в выбранной папке плюс один. Для агента и терминала в форме отдельные черновики имен.

В поле выбранной модели новой сессии слева показан логотип провайдера. Логотипы включены в плагин (shared/logos.shared.ts), выпадающий список не меняется.

В настройках проекта блок «Отображаемые разделы»: кнопки Eye/EyeOff независимо скрывают или показывают «Области» и «Пулы». Можно скрыть оба. Настройка сохраняется в hiddenSections проекта, данные разделов не удаляются. При скрытии выбранного раздела показывается первый оставшийся видимый.

Настройки проекта: вкладки «Области» и «Пулы» содержат настройки соответствующего раздела. Первая настройка - «Показывать в сайдбаре», сохраняется сразу и независимо для каждого раздела.

Быстрое создание агента не ждет каталог провайдеров: при известной модели кнопка доступна сразу, до загрузки сохраняются permissions и reasoning последней сессии. Общая форма действует для новой области и новой сессии.

Каталог создания публикует готовые настройки постепенно, не ожидая других провайдеров. RPC создания не ждет общий каталог: модель и параметры проверяет Paseo при создании. События агентов применяются через shared/sidebar-agent-updates.ts без полной перезагрузки сайдбара на каждое событие. Проверки и границы: docs/agent-creation.md.

На всех платформах переход к агенту идет через openScreen и экран jump к navigation.openAgent (client/agent-navigation.ts). Это закрывает мобильный сайдбар и показывает панель чата даже для уже открытой вкладки. Прямой workspace deep link с ?open= только ставит открытие вкладки в очередь и не заменяет эту навигацию. Каждое нажатие имеет свой идентификатор перехода. Закрытие агента закрывает меню сразу, не блокирует остальные сессии, не ждет reloadAll и не показывает success-попап. Ошибки архивации видны пользователю. Проверка: tests/session-settings/archive-navigation.mjs.

Снимок провайдеров от нативного клиента может иметь пустой entries при заполненном compactSnapshot. shared/provider-cache.ts раскрывает официальный компактный формат до проверки готовности, обрабатывает обновления только с хешем и разделяет кеши хостов. Нельзя возвращать SDK waitForReady без нормализации: пустой entries в wire-режиме не означает готовый пустой каталог. Проверка: node tests/providers/live-wire.mjs, без вызова модели.
