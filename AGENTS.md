# Инструкция для AI-агентов: Штаб Paseo (Paseo HQ)

Этот документ предназначен для AI-ассистентов (Claude, Codex, Antigravity, Cursor и других), работающих в проектах с установленным плагином **Paseo HQ (Штаб)**. Здесь описано, как устроен плагин, как правильно оформлять артефакты в чате и как помогать пользователю настраивать окружение.

---

## 1. Архитектура и возможности плагина

Плагин **Paseo HQ** превращает рабочий стол Paseo в единый командный центр:
- **Проекты, области и сессии («Штаб»)**. Области группируются по проектам, получают короткие названия и могут переноситься между проектами.
- **Интерактивные артефакты**: автоматическое распознавание HTML, SVG и Markdown в чате, превращение их в интерактивные карточки с песочницей, скачиванием, просмотром во весь экран и доставкой в Telegram.
- **Галерея артефактов (`/surface/artifacts`)**: единая библиотека созданных документов с фильтрами по проектам, типам и поиском, а также возможностью удаления ненужных карточек.
- **Монитор воркеров (Workers)**: мониторинг контейнеров (LXC / Docker) и окружений разработчиков/агентов через cgroup v2.
- **Системные службы (Host Services)**: мониторинг состояния systemd-сервисов хоста без прав root.
- **Учет расходов моделей (Usage)**: отслеживание токенов и лимитов провайдеров.

## 2. Как агенту генерировать артефакты

Когда вы создаете для пользователя дашборд, схему, интерактивный калькулятор или документ, оформляйте их так, чтобы Штаб распознал их как интерактивные артефакты.

### HTML-артефакты (дашборды, отчеты, веб-страницы)
Используйте блок ````html` с указанием `filename`:

````html filename="report.html"
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8" />
  <title>Финансовый отчет Q3</title>
  <style>
    body { font-family: system-ui, sans-serif; padding: 20px; background: #0f172a; color: #f8fafc; }
    .card { background: #1e293b; padding: 16px; border-radius: 8px; margin-bottom: 12px; }
  </style>
</head>
<body>
  <h1>Финансовый отчет Q3</h1>
  <div class="card">
    <p>Выручка: +24%</p>
  </div>
</body>
</html>
````

**Что происходит в интерфейсе:**
1. Штаб автоматически превращает блок в интерактивную карточку в ленте сообщений.
2. Пользователь может нажать **«В новой вкладке»** для открытия на весь экран или **«Скачать»**.
3. Если настроен Telegram-бот, HTML-артефакт автоматически прилетает в Telegram пользователя, где его можно мгновенно открыть с телефона во встроенном Safari.

### SVG-артефакты (архитектурные схемы, диаграммы)
Используйте блок ````svg` с указанием `filename`:

````svg filename="network-topology.svg"
<svg viewBox="0 0 400 200" xmlns="http://www.w3.org/2000/svg">
  <title>Схема сети</title>
  <rect width="100%" height="100%" fill="#18181b"/>
  <circle cx="100" cy="100" r="40" fill="#3b82f6"/>
  <circle cx="300" cy="100" r="40" fill="#10b981"/>
  <line x1="140" y1="100" x2="260" y2="100" stroke="#71717a" stroke-width="2"/>
  <text x="100" y="105" fill="#ffffff" text-anchor="middle" font-size="12">Frontend</text>
  <text x="300" y="105" fill="#ffffff" text-anchor="middle" font-size="12">Backend</text>
</svg>
````

### Markdown-документы (планы, спецификации, брифы)
Чтобы блок Markdown превратился в карточку артефакта, явно укажите атрибут `filename="...md"` или тег `artifact:markdown`:

````markdown filename="architecture-plan.md"
# Архитектурный план сервиса

1. Микросервис аутентификации на Go.
2. База данных PostgreSQL 16.
3. Очередь задач RabbitMQ.
````

> **Важно:** Обычные текстовые рассуждения, списки задач и фрагменты кода в чате без тега `filename="...md"` **НЕ** становятся артефактами. Это сделано специально, чтобы лента чата не засорялась карточками.

### Сохранение файлов на диск проекта
Если агент генерирует файлы на диске, сохраняйте артефакты в подкаталог `artifacts/` корня репозитория (например, `my-project/artifacts/summary.html`).
Штаб автоматически обнаруживает файлы в каталоге `artifacts/` после завершения хода агента и регистрирует их в галерее. Файлы в корне проекта (`README.md`, `package.json`, `.env`) игнорируются сканером, чтобы библиотека оставалась чистой.

## 3. Взаимодействие агентов и ссылки

В Штабе проект содержит области (workspace в Paseo). Сессия - это вкладка области. Сессии бывают двух видов: агенты с перепиской и терминалы. У агента есть идентификатор `agentId` (UUID).

### Формат ссылок на агентов
- **Нативный Deep Link**: `paseo:///h/<serverId>/agent/<agentId>` (например, `paseo:///h/local/agent/073a4a42-1c2f-4516-aa2c-1bf26869bbe2`). По клику открывает приложение Paseo прямо на нужной вкладке.
- **Web URL**: `https://<host>/h/<serverId>/agent/<agentId>`.
- **Короткий или полный ID**: `073a4a4` или `073a4a42-1c2f-4516-aa2c-1bf26869bbe2`.

В сайдбаре нажатие на область раскрывает ее сессии. Плюс у проекта открывает форму новой области с выбором первой вкладки.

Иконка с четырьмя плитками открывает «Функционал области». Под заголовком слева расположен квадрат с эмодзи, за ним название с карандашом и справа кнопка генерации. Пустой квадрат открывает тот же выбор эмодзи. Карандаш ставит каретку в конец названия и сменяется галочкой сохранения. Кнопка генерации предлагает название по верхнему агенту в списке. В ряду быстрых действий плюс создает агента, иконка терминала открывает терминал, а шестеренка в Git-области открывает настройку ветки по умолчанию.

Раздел «Сессии» показывает открытых агентов и терминалы области. Список вкладок с файлами и браузером хранится в клиенте Paseo и через SDK плагина недоступен. Фильтры «Все», «Агенты» и «Терминалы» меняют состав списка. Нажатие на строку открывает вкладку. Меню агента в панели и в сайдбаре позволяет скопировать ссылку, переименовать, перезагрузить или закрыть агента. Под названием терминала видна его рабочая папка при создании. В его меню можно скопировать этот путь или закрыть терминал с подтверждением.

В разделе «Закрытые сессии» внизу панели можно открыть переписку архивных агентов текущей области. Paseo удаляет запись терминала при закрытии. Архивация области завершает ее терминалы и может удалить ее выделенный worktree вместе с незакоммиченными файлами.

У всех сессий области общая рабочая папка Git. Если в настройках выбрана ветка по умолчанию, Штаб проверяет текущую ветку перед созданием агента. Бейдж в списке показывает ветку в момент запуска агента, если Штаб ее записал.

### Как изучить переписку агента по переданной ссылке
Когда пользователь просит:
> *«Посмотри, что обсуждали с агентом paseo:///h/local/agent/073a4a42-1c2f-4516-aa2c-1bf26869bbe2»*

1. Извлеките `agentId` из ссылки (или используйте утилиту `paseo-chat`, которая сделает это автоматически).
2. Запустите чтение истории через bash:
   ```bash
   # Прочитать последние 20 сообщений
   paseo-chat read "paseo:///h/local/agent/073a4a42-1c2f-4516-aa2c-1bf26869bbe2" --tail 20

   # Или прочитать полную курированную историю
   paseo-chat read <agentId>
   ```
   Либо штатной командой Paseo: `paseo agent logs <agentId>`.
3. Изучите полученный транскрипт и выполните задачу пользователя.

### Как отправить сообщение или задачу другому агенту
Если вам нужно отправить результат или поручение другому агенту:
```bash
paseo-chat send <agent-id-or-url> "Привет! Я проверил ветку, тесты проходят. Можешь продолжать деплой."
```
Либо штатной командой:
```bash
paseo agent send --behavior steer <agentId> "Текст сообщения"
```
**Важно:** Paseo автоматически определяет отправителя через переменную окружения `PASEO_AGENT_ID`. Агент получит сообщение в мягком режиме `steer` (без прерывания текущих операций) с пометкой, от какого агента оно пришло.

### Список доступных агентов
```bash
paseo-chat ls
```
Показывает активных агентов, их статус (idle/running), рабочий каталог и тему.

## 4. Удаление артефактов и безопасность данных

- Пользователь может удалить любой артефакт в Галерее артефактов (`/surface/artifacts`):
  - По клику на иконку корзины на карточке в списке.
  - По кнопке «Удалить» в режиме полноэкранного просмотра.
- При удалении артефакт удаляется из локальной галереи (`~/.paseo/artifacts/`), но если артефакт ранее был выгружен в облако (Яндекс Диск или S3), **внешняя копия в облаке не удаляется**.

## 5. Настройка доставки в Telegram

Для автоматической отправки HTML-страниц и ручной отправки любых артефактов пользователю в Telegram:

1. Создайте файл `~/.paseo/telegram.env` со следующими переменными:
   ```env
   TELEGRAM_BOT_TOKEN="123456789:ABCdefGHIjklMNOpqrsTUVwxyz"
   TELEGRAM_CHAT_ID="987654321"
   ```
   Либо задайте переменные окружения в `~/.bashrc`:
   ```bash
   export TELEGRAM_BOT_TOKEN="123456789:ABCdefGHIjklMNOpqrsTUVwxyz"
   export TELEGRAM_CHAT_ID="987654321"
   ```

2. После перезапуска плагина (`paseo plugin reload paseo-hq`):
   - Все новые HTML-документы из чата будут автоматически отправляться в диалог с ботом.
   - В каждой карточке артефакта появится кнопка **«В Telegram»**.

## 6. Настройка монитора воркеров (`~/.paseo/workers.json`)

Если вы используете изолированные контейнеры (LXC, Docker) или отдельные рабочие окружения для агентов, создайте файл `~/.paseo/workers.json`:

```json
[
  {
    "id": "agent-1",
    "name": "Frontend Agent",
    "avatar": "🧑‍💻",
    "role": "React / Next.js",
    "container": "frontend-box",
    "user": "agent",
    "cgroupPath": "/sys/fs/cgroup/lxc.payload.frontend-box"
  },
  {
    "id": "agent-2",
    "name": "Backend Agent",
    "avatar": "👨‍💻",
    "role": "Go / PostgreSQL",
    "container": "backend-box",
    "user": "agent",
    "cgroupPath": "/sys/fs/cgroup/system.slice/docker-backend.scope"
  }
]
```

Штаб читает стандартный cgroup v2 интерфейс (`cpu.stat`, `cpu.max`, `memory.current`, `pids.current`) и в реальном времени отображает загрузку ядер процессора, потребление памяти и активность воркеров в шапке панели.

## 7. Настройка системных служб (`~/.paseo/services.json`)

Для отслеживания ключевых systemd-служб сервера создайте файл `~/.paseo/services.json`:

```json
{
  "docker.service": ["Docker", "Демон управления контейнерами"],
  "nginx.service": ["Nginx", "Веб-сервер и обратный прокси"],
  "ssh.service": ["SSH", "Служба защищенного удаленного доступа"],
  "postgresql.service": ["PostgreSQL", "Основная база данных"]
}
```

Кнопка **[Server]** в верхней панели Штаба откроет таблицу состояния служб в реальном времени.

## 8. Команды управления плагином

Если пользователь просит вас настроить, обновить или проверить плагин:

```bash
# Установка и активация
paseo plugin add /path/to/paseo-hq

# Проверка списка активных плагинов
paseo plugin ls

# Перезапуск плагина после изменений в коде или настройках
paseo plugin reload paseo-hq

# Логи плагина
paseo plugin logs paseo-hq

# Проверка типов и запуск тестов
npm --prefix /path/to/paseo-hq run typecheck
npm --prefix /path/to/paseo-hq test
```

## 9. Google AI Pro, Gemini API и живые квоты

По вопросам подключения Gemini API, квот, Pro-кредитов и биллинга сначала
вызовите инструмент hq_gemini_help, если он доступен. Он возвращает каноническую
справку и текущую конфигурацию выбранного хоста без секретов. Тот же текст в
[docs/gemini-api.md](docs/gemini-api.md) и в карточке «Как подключить».
Не путайте подписку Pro с пулом API, ограничения с расходом, снимок с живыми
данными. Конкретные Project ID хранятся только на хосте в gemini-api.json,
не в общей инструкции. Наличие ключа не доказывает доступ OAuth/IAM.
Не включайте биллинг и не покупайте кредиты без поручения владельца.
