# Paseo Workspace HQ (Штаб)

Полнофункциональный плагин центрального штаба для [Paseo](https://paseo.sh): проекты, области, сессии, интерактивные артефакты, мониторинг воркеров команды, системных служб и учет расхода моделей.

---

## Возможности

1. **Проекты, области и сессии («Штаб»)**:
   - Проект содержит области (workspace в Paseo). Сессия в Штабе - это вкладка области. У сессий два вида: агенты с перепиской и терминалы.
   - Кастомные аватарки проектов с автоматическим кадрированием.
   - Закрепление проектов в настройках: они показываются наверху, остальные сортируются по активности.
   - Области сортируются по времени последнего сообщения. Нажатие на область раскрывает ее сессии. Слева от названия и модели агента виден его статус. Под названием терминала указан путь к его рабочей папке при создании.
   - Плюс у проекта открывает форму новой области. Начальное название - «Новая сессия». В форме можно изменить название и выбрать, какая вкладка откроется первой: агент или терминал. Новый агент использует настройки последнего агента проекта, а в новом проекте - последнего агента хоста или доступного провайдера.
   - Иконка с четырьмя плитками в строке области открывает ее панель. В ряду быстрых действий можно создать агента или терминал, закрепить область, скопировать путь к корню проекта, открыть настройки, перенести или архивировать область.
   - Под заголовком «Функционал области» слева расположен квадрат с эмодзи, за ним название, справа кнопка генерации. Карандаш ставит каретку в конец названия и сменяется галочкой сохранения. Квадрат открывает выбор эмодзи и остается пустым, когда иконка не задана. Кнопка генерации предлагает название по верхнему агенту в списке. Модель выбирается в настройках проекта.
   - Иконка переноса открывает отдельное окно с выбором проекта, переносом истории последнего агента и архивацией исходной области.
   - Шестеренка в Git-области открывает настройку ветки по умолчанию.
   - Раздел «Сессии» показывает открытые вкладки с фильтрами «Все», «Агенты» и «Терминалы». У агента одно и то же меню в раскрытой области и в панели области. В меню можно скопировать ссылку, переименовать, перезагрузить или закрыть агента.
   - В меню терминала можно скопировать его рабочий путь или закрыть терминал с подтверждением завершения процессов.
   - Внизу панели в разделе «Закрытые сессии» можно открыть переписку архивных агентов этой области. Paseo удаляет запись терминала при закрытии. При архивации области Paseo также завершает ее терминалы и может удалить ее выделенный worktree вместе с незакоммиченными файлами.
   - В Git-области настройка «Ветка по умолчанию» задает ветку для создания агентов через Штаб. Все сессии области используют одну рабочую папку. Перед созданием агента переключите ее на выбранную ветку, если она отличается от текущей. Для параллельной работы в разных ветках используйте отдельные области с worktree.
   - Бейдж в панели области показывает ветку в момент запуска агента. Штаб записывает ее для новых агентов. У старых агентов без записи и у агентов, запущенных с detached HEAD, бейдж скрыт.

2. **Взаимодействие агентов (`bin/paseo-chat`)**:
   - Передача ссылок на агентов для изучения контекста.
   - Утилита `bin/paseo-chat` (`paseo-chat ls`, `read <url-or-id>`, `send <url-or-id> <текст>`).
   - Нативная маршрутизация сообщений между агентами через очередь Paseo с автоматической фиксацией отправителя и режимом `steer`.

3. **Интерактивные артефакты**:
   - Автоматическое распознавание блоков кода (`html`, `svg`, `markdown`) в чатах и преобразование их в интерактивные карточки с песочницей и кнопками действий.
   - Галерея артефактов (`/surface/artifacts`) с фильтрацией по проектам, поиском и возможностью удаления ненужных карточек.
   - Автоматическая отправка новых HTML-страниц в Telegram через встроенный клиент Telegram Bot API без дублирования.
   - Ручная отправка любых артефактов в Telegram в один клик.
   - Опциональный облачный экспорт (S3 / rclone / WebDAV / Яндекс Диск).
   - Индексация готовых документов из папки `artifacts/` в корне проекта без захламления репозиторными файлами.

4. **Команда и воркеры (Workers Monitor)**:
   - Мониторинг изолированных сред разработчиков и агентов (LXC-контейнеры, Docker, cgroup v2).
   - Снятие метрик в реальном времени: нагрузка на процессор (с учетом лимита ядер), потребление ОЗУ, количество процессов, статус активности.
   - Плашка команды в шапке панели и полноэкранный диалог управления.

5. **Системные службы (Host Services)**:
   - Мониторинг ключевых systemd-служб и таймеров хоста без sudo и сторонних демонов.
   - Настраиваемый список отслеживаемых сервисов.

6. **Интеграция с Git**:
   - Поиск и клонирование репозиториев из GitHub и GitLab (включая приватные инсталляции) в один клик.
   - Автоматическое создание областей.

7. **Лимиты и расход моделей**:
   - Трекинг расхода токенов и баланса провайдеров (Claude, OpenAI, DeepSeek, Google Gemini, Antigravity).
   - Отдельная карточка Gemini API: пики RPM, TPM и RPD по моделям из датированного снимка AI Studio. Ссылки на текущие лимиты, расход, биллинг и кредиты Pro.

### Gemini API в лимитах

Кнопка «Как подключить» в карточке содержит настройку проекта, выбор входа
Google и справку по Pro, биллингу и ошибкам доступа. Живой источник читает
ограничения Service Usage по моделям раз в минуту. Расход Monitoring пока
не подключен. Наличие Pro не доказывает активацию кредитов или платный API.

[Полная инструкция](docs/gemini-api.md). Агентам на хосте доступен инструмент
`hq_gemini_help`: тот же текст и текущая настройка проекта без credentials.
После обновления инструмент появляется при следующем открытии агента.
Команда `usage.gemini-api.help` возвращает эту же справку через RPC.

Серверная настройка хранится в `~/.paseo/gemini-api.json` (или `PASEO_HOME`).
Ее проще сохранить через интерфейс. Ни ключ генерации, ни OAuth-токен туда
не записываются. Источник авторизации - существующий вход agy либо gcloud.
Пул `free`, `paid`, `paid-2`, `paid-3` выбирается по тарифу проекта в AI Studio,
это не автоматическая проверка биллинга. Конфигурация не содержит данных владельца
и не поставляется другим пользователям.

Исторические снимки `gemini-api-usage.json` поддерживаются для старых настроек,
явно отмечены датой и периодом. Настроенный живой источник никогда не подменяется
снимком при ошибке. Значения protobuf zero и -1 (нет ограничения) различаются,
отсутствующий счетчик означает «Нет данных». Цена и остаток денег не вычисляются
из количества запросов.

Проверки: `npm run test:limits`, `npm run smoke:limits` и
`npm run smoke:limits -- --live`. Для живого smoke нужен доступ к демону через
`PASEO_DAEMON_URL` и `PASEO_PASSWORD`, если на нем настроен пароль.

## Установка

Плагин устанавливается штатной командой Paseo:

```bash
# Добавить и активировать плагин из локальной папки
paseo plugin add /path/to/paseo-hq

# Проверить статус
paseo plugin ls

# При внесении изменений в код
paseo plugin reload paseo-hq
```

## Инструкция для AI-агентов

В корне плагина находится файл **`AGENTS.md`** с подробным описанием правил работы для AI-ассистентов (Claude, Codex, Antigravity, Cursor):
- Как правильно размечать интерактивные артефакты (`html`, `svg`, `markdown`) в кодовых блоках.
- Где сохранять готовые файлы на диске проекта (`artifacts/`), чтобы они автоматически попадали в галерею.
- Как настраивать переменные Telegram и мониторинга для пользователя.

Если вы настраиваете рабочее место через AI-агента, просто попросите его:
> *«Прочитай AGENTS.md в плагине paseo-hq и настрой мне Telegram и мониторинг воркеров»*.

## Настройка конфигурации

Плагин работает из коробки с разумными значениями по умолчанию, но его можно полностью настроить под ваше окружение.

### 1. Переменные окружения

Задаются в профиле оболочки (`~/.bashrc` / `~/.zshrc`) или в конфигурации демона Paseo (`~/.paseo/config.json`):

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `PASEO_REPOS_DIR` | Корневой каталог для поиска и клонирования проектов | `~/repos` |
| `PASEO_ARTIFACTS_DIR` | Папка для хранения сохраненных артефактов и индексов | `~/.paseo/artifacts` |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота для отправки HTML и документов | *(отключено, если не задано)* |
| `TELEGRAM_CHAT_ID` | Chat ID в Telegram, куда отправлять документы | *(отключено, если не задано)* |
| `PASEO_CLOUD_UPLOAD_CMD` | Шаблон команды для облачного экспорта (S3/rclone) | *(отключено, если не задано)* |
| `PASEO_WORKERS_CONFIG` | Путь к файлу конфигурации воркеров | `~/.paseo/workers.json` |
| `PASEO_SERVICES_CONFIG` | Путь к файлу конфигурации служб | `~/.paseo/services.json` |

#### Пример отправки в Telegram:
```bash
export TELEGRAM_BOT_TOKEN="123456789:ABCdefGHIjklMNOpqrsTUVwxyz"
export TELEGRAM_CHAT_ID="987654321"
```
После этого карточки артефактов получают активную кнопку **«В Telegram»**, а все создаваемые HTML-артефакты автоматически прилетают в личные сообщения бота (где на iPhone открываются во встроенном Safari-просмотрщике Telegram).

#### Пример облачного экспорта:
```bash
export PASEO_CLOUD_UPLOAD_CMD='rclone copy {file} mycloud:artifacts/{project}/ && rclone link mycloud:artifacts/{project}/{name}'
```

### 2. Мониторинг воркеров команды (`~/.paseo/workers.json`)

Создайте файл `~/.paseo/workers.json` (образец лежит в `workers.example.json`):

```json
[
  {
    "id": "alex",
    "name": "Алексей",
    "avatar": "🧑‍💻",
    "role": "Fullstack Agent",
    "container": "alex-work",
    "user": "alex",
    "activityPath": "/run/workers/alex-status.json",
    "cgroupPath": "/sys/fs/cgroup/lxc.payload.alex-work"
  },
  {
    "id": "sergey",
    "name": "Сергей",
    "avatar": "👨‍💻",
    "role": "DevOps / Infra",
    "container": "sergey-work",
    "user": "sergey",
    "activityPath": "/run/workers/sergey-status.json",
    "cgroupPath": "/sys/fs/cgroup/lxc.payload.sergey-work"
  }
]
```

- `cgroupPath`: путь к cgroup контейнера (LXC или Docker), откуда читаются метрики CPU (`cpu.stat`, `cpu.max`), RAM (`memory.current`, `memory.max`) и число процессов (`pids.current`).
- `activityPath`: опциональный JSON-файл со временем последнего запроса агента и входа (`agentLast`, `lastMessage`, `lastSsh`).

---

### 3. Мониторинг служб хоста (`~/.paseo/services.json`)

Создайте файл `~/.paseo/services.json` (образец лежит в `services.example.json`):

```json
{
  "docker.service": ["Docker", "Демон управления контейнерами"],
  "nginx.service": ["Nginx", "Веб-сервер и обратный прокси"],
  "ssh.service": ["SSH", "Служба защищенного удаленного доступа"],
  "postgresql.service": ["PostgreSQL", "Основная база данных"]
}
```

Кнопка `[Server]` в верхней панели Штаба покажет интерактивную таблицу с их статусом в реальном времени.

## Разработка и проверка кода

В проекте настроена строгая проверка типов TypeScript и юнит-тесты:

```bash
# Проверка типов
npm run typecheck

# Запуск юнит-тестов
npm test
```

`npm run smoke:sessions` проверяет фильтры сессий, историю агентов, создание области и выбор ветки в браузере на ширине 390 и 1280 пикселей. Для прогона нужны Paseo CLI, провайдер Codex и Chromium для Playwright. Тест запускает отдельный локальный демон с тестовыми проектами.

## Подключить GitHub или GitLab с телефона

Откройте Git в Штабе. В карточке нужного сервиса нажмите «Войти» либо «Войти
заново», скопируйте одноразовый код и откройте страницу сервиса. Подтвердите вход
в браузере: Штаб сам обновит список. Вход можно отменить, не отключая текущий
аккаунт. Нужны установленные `gh` и `glab` с поддержкой device login.

Подключение сохраняется для выбранного сервера Paseo и используется его окнами.
Пароль вводится только на сайте сервиса, сохраненными ключами управляет CLI.
После входа клонирование использует HTTPS и credential helper этого CLI.

Список включает личные репозитории, доступные организации GitHub и проекты групп
GitLab, включая подгруппы. Страницы загружаются целиком, поиск идет по доступному
списку. При смене аккаунта старые записи сбрасываются. Ошибки доступа и сети
показываются явно. Доступ ограничен разрешениями аккаунта и OAuth-приложения:
организация может требовать отдельного одобрения или SSO.

Проверки без изменения действующих аккаунтов:

```bash
npm run test:git
npm run smoke:git
```

Браузерный прогон использует настоящий экран и сервис входа с локальным CLI
для имитации подтверждения, отмены и ошибки. При `--live` список репозиториев
читается из установленного Штаба, вход остается изолированным. Передайте
`PASEO_PASSWORD`, `PASEO_GIT_EXPECT_USER` и `PASEO_GIT_EXPECT_NAMESPACE` в окружении.

## Интерактивные ответы внутри Штаба

Штаб сам отображает блоки `ui` и `app`: карточки, формы, таблицы, графики,
диаграммы и интерактивный HTML в песочнице. Ответ может содержать одновременно
интерактивную карточку и HTML, SVG или Markdown-документ.

Галерея «Компоненты Штаба» открывается через командный центр
или `/genui-gallery`. `/genui-demo` вставляет пример без запроса к модели.
Настройки «Интерактивные ответы» управляют инструкциями для новых агентов,
сетевыми запросами и дополнительными папками для `Load`, `Snippet` и `Image`.
По умолчанию доступны рабочий каталог агента, хранилище его переписки и `/tmp`.
Инструмент `render_ui` проверяет и показывает карточку из того же кода.

В карточке нажмите «Выделить текст», чтобы открыть абзацы, списки и черновики
в полях только для чтения. В них можно выбрать фрагмент, а кнопкой «Копировать»
забрать весь текст блока без Markdown-разметки. «Вернуть оформление» закрывает
этот режим. Это позволяет обойти ограничение `Text` в iOS, где `selectable`
предлагает копирование абзаца целиком. Таблицы и другие виджеты сохраняют свой вид.

Исходники входят в этот репозиторий, зависимости от npm-пакета
`paseo-plugin-genui` нет. Компоненты меняются в `client/genui/components`,
язык и инструкции - в `shared/genui`, обработчики и чтение файлов - в
`server/genui`, примеры - в `genui/gallery`. Происхождение и лицензии
зафиксированы в [NOTICE](NOTICE) и [genui/UPSTREAM.json](genui/UPSTREAM.json).

Проверка без моделей:

```bash
npm ci
npm run typecheck
npm test
npm run test:genui
npm run smoke:genui
npm run check:genui-client
HERMES_EXECUTABLE=/path/to/hermes npm run check:genui-hermes
```

`check:genui-hermes` запускает настоящий загрузчик файлов и интерпретатор в Hermes
CLI (исполняемый `hermes`, не `hermesc`). Runtime доступен в
[официальном Linux release](https://github.com/meta/hermes/releases/download/v0.13.0/hermes-cli-linux.tar.gz).
Проверяет совместную загрузку JSON для Acceptance и текста для Draft в обоих
порядках ответа и отказ одного RPC. Планировщик React и файловый RPC имитируются,
форматирование Intl не проверяется. Эта проверка ловит ошибку мобильного движка,
которую V8/Chromium не воспроизводит: асинхронные замыкания в цикле видят последний
ключ файла. Отчет сохраняется рядом с отчетом браузера (`hermes.json`).

`check:genui-client` запускает регистрацию через настоящий валидатор установленного
Paseo, включая допустимые типы преобразований ленты. Нужен CLI `paseo` в PATH
либо `PASEO_WEB_BUNDLE_DIR`, указывающий на каталог web-ui/_expo/static/js/web.

Для браузерного прогона нужен Chromium из Playwright либо путь в
`PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Он проверяет настоящие компоненты через
React Native Web на ширине 1280 и 390, изменение состояния, формирование ответа,
загрузку файла и песочницу HTML. Компоненты оболочки Paseo заменены адаптерами
из `tests/genui/host.tsx`, отправка ответа в модель не выполняется. Снимки и
отчет сохраняются в `/tmp/opencode/hq-genui` или `GENUI_SMOKE_OUTPUT`.

Проверка чтения файлов и галереи через установленный Штаб:

```bash
PASEO_SMOKE_AGENT_ID=<existing-agent-id> npm run smoke:genui -- --live
```

Для защищенного демона передайте `PASEO_PASSWORD` через окружение. Прогон читает
данные существующего агента, не запускает модель и не отправляет ему сообщений.

При обновлении существующей установки сначала проверьте новую версию Штаба,
затем отключите отдельный `genui`: `paseo plugin disable genui`. Две версии
одновременно регистрируют одинаковые команды и инструмент. Настройки старого
плагина не переносятся автоматически, при индивидуальных настройках скопируйте
их в «Интерактивные ответы» перед переключением. Штаб сохраняет формат обычных блоков
ui/app и ключи локального состояния. Старые отдельные строки `render_ui`/demo
остаются привязаны к ID плагина `genui`: без него Paseo не показывает эти строки.

## Восстановление истории DeepSeek

Загрузчик старых сессий DSH v4 восстанавливает сообщения, инструменты и картинки
из локального хранилища вложений. Записи согласований, задач и повторных запросов
не мешают показу переписки. Целостность картинок проверяется по SHA-256, неизвестный
формат по-прежнему вызывает явное предупреждение.

Регрессия и повторное восстановление проверяются без запросов к модели:

```bash
node --test server/deepseek-replay.test.mjs
```

Для проверки существующих сессий укажите `PASEO_REPLAY_CHECK_TARGETS` - путь к
локальному JSON-массиву объектов `{ "sid": "session-id", "cwd": "/project" }`.
Тест прочитает каждую историю дважды и проверит совпадение результатов без изменений
файлов. Метаданные личных переписок не добавляйте в репозиторий.

### Просмотр файлов в ответах

Карточка `File` открывает текст внутри ответа на телефоне и компьютере. Закрытие возвращает карточку в исходное состояние, адрес workspace не меняется. Недоступные и нетекстовые файлы показывают ошибку, чтение ограничено текущим workspace и разрешенными каталогами GenUI. Ожидание ограничено 15 секундами. Файлы за пределами разрешенных каталогов не открываются через обход доступа.

Регрессия: `npm run smoke:genui` проверяет открытие, содержимое, закрытие и отказ доступа с неизменным URL на ширине 390 и 1280.
