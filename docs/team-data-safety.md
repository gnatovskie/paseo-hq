# Данные совместных Git-досок

## Общие и личные задачи

В общий `hq.json`, коммиты и push попадают только задачи без `personal: true`.
Личные задачи хранятся отдельно на текущем хосте и добавляются к общей доске
при чтении. Это граница между хостами команды, а не отдельная авторизация
для разных браузеров или людей с доступом к одному демону/системному пользователю.

Локальное состояние находится в
`$PASEO_HQ_TEAM_DIR/local-boards/<sha256>.json`. По умолчанию корень —
`~/.local/state/paseo-hq`; ключ зависит от URL репозитория и ветки.
Отключение и повторное подключение той же доски сохраняет личные задачи.
Каталог создаётся с правами `0700`, файл — `0600`, вне Git-каталога доски.
Не помещайте этот каталог в общие репозитории или публичные резервные копии.

Пока есть неотправленные изменения, тот же локальный файл содержит полный
черновик и списки удалений. После успешной отправки подтверждённой версии
в нём остаются только личные задачи. Замена файла атомарная; повреждённый
JSON вызывает ошибку, а не заменяется пустой доской.

## Обновление со старой версии

Старый локальный `hq.pending.json` переносится при восстановлении черновика:
сначала записывается новое состояние вне Git, затем удаляется старый файл.
Запускайте только один экземпляр плагина, работающий с этим локальным состоянием.

Задачи `personal: true`, уже записанные старой версией в общий `hq.json`,
**не становятся личными задачами текущего хоста автоматически**: нельзя
достоверно определить их владельца. Они не отображаются из общей копии
и исключаются из следующей записи `hq.json`. Для восстановления таких задач
нужно согласовать локальный перенос с их владельцами.

Исправление не удаляет ранее опубликованные данные из истории Git, старых
клонов, резервных копий или чужих копий репозитория. Если утечка уже произошла,
её устранение требует отдельного согласованного действия владельцев.
Старая версия плагина не понимает новое локальное хранилище; сохраните его
резервную копию перед откатом.

## Правки во время отправки

Каждый черновик имеет монотонную ревизию. Завершённый push подтверждает только
тот снимок, который отправлялся. Более новая правка или удаление остаются
в памяти и локальном pending-состоянии до следующей отправки, в том числе
после перезапуска. Локальные записи и подтверждения выполняются последовательно.
При неудачном push черновик остаётся неотправленным.

Прямой `saveBoard()` для подключённой доски использует тот же живой черновик
и подтверждение ревизии, что и интерфейс. Вместе со снимком сохраняются все
накопленные удаления задач и участников, включая восстановленные из pending.
Пока уже идёт другая Git-синхронизация,
он возвращает ошибку до сохранения; обычные UI-правки через `applyBoardChange()`
не блокируются. Для отдельного клиента с неподключённым pending-черновиком
нужно сначала подключить доску: прямое сохранение не перезаписывает такой черновик.

## Регрессионные проверки

```sh
node --test server/team-privacy.test.mjs server/team.server.test.mjs shared/team-model.test.mjs
```

Тесты используют временные локальные bare Git-репозитории. Они проверяют
отсутствие новых личных задач в истории, чтение с другого хоста, перезапуск,
переподключение, смену приватности, удаление, миграцию pending, отказ при
повреждении файла, одновременные первые правки, прямой `saveBoard()` при существующем черновике
и повтор после неудачного push.
В тесте гонки push действительно блокируется Git-хуком до сохранения новой правки.
