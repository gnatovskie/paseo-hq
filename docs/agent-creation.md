# Настройки нового агента

В окнах «Новая область» и «Новая сессия» можно выбрать модель, permissions и уровень рассуждения до создания агента. Permissions и уровень рассуждения показаны компактными строками с выпадающими селекторами. Списки вариантов открываются только по нажатию.

Начальные значения наследуются от последней сессии проекта. Список permissions берется из каталога выбранного провайдера, уровни рассуждения - из определения выбранной модели. При смене модели сохраняются совместимые значения, а несовместимые заменяются объявленными значениями по умолчанию. Если провайдер или модель не предлагает настройку, форма сообщает об этом и не передает неподдерживаемое значение.

Проверки без запросов к моделям:

```sh
node --test shared/agent-creation-options.test.mjs
PASEO_CHROMIUM_EXECUTABLE=<путь к Chromium> node --test tests/session-settings/creation-names.mjs
```

Поле названия агента изначально пустое. Без введенного имени агент создается без явного названия, чтобы работало автоматическое именование после начала диалога. «Агент без названия» используется только как запасная подпись в списке. У терминала поле изначально содержит `Terminal N`, где N - число открытых терминалов в выбранной папке плюс один, как в Paseo. Имена агента и терминала редактируются независимо и сохраняются при переключении типа в форме. Отображаемое имя терминала передается при создании.

Готовые настройки провайдера показываются по мере поступления каталога. Медленный другой провайдер не задерживает permissions и reasoning уже готовой модели. Пока выбранный провайдер загружается, сохраняются унаследованные значения. Создание передает выбор прямо в Paseo, который проверяет модель и настройки, без дополнительного ожидания полного каталога в RPC Штаба.

События изменения агента обновляют его строку в памяти. Они не запускают повторную загрузку всех проектов, областей и агентов. Периодическая сверка списков остается, включая получение размещения новых агентов от старых хостов.

Проверка этих ограничений без обращения к моделям:

```sh
node --test shared/provider-cache.test.mjs shared/sidebar-agent-updates.test.mjs server/creation-latency.test.mjs shared/agent-creation-options.test.mjs
```

На iOS и Android созданный агент открывается прямой ссылкой на вкладку известной области (`/h/<host>/workspace/<workspace>?open=agent:<id>`). Промежуточный экран плагина для этого не нужен. В браузере остается навигация через SDK без перезагрузки страницы. Если область неизвестна, используется прежний переход по ID агента.

Нативный плюс Paseo открывает локальный черновик. Штаб создает агента на сервере с выбранными настройками до открытия чата. Это разные операции: проверка скорости Штаба должна завершаться появлением поля сообщения, а не только ответом RPC. Браузерный тест выше теперь проверяет этот этап и прямой маршрут вкладки. Скорость системного deep link на iOS этим тестом не измеряется.

## Формат каталога на телефоне

Клиент Paseo может возвращать сжатый `compactSnapshot` с пустым `entries`. Это готовые данные, а не отсутствие провайдеров. Штаб раскрывает их официальным `expandProviderSnapshot`: permissions находятся в `modes`, уровни рассуждения - в `models[].thinkingOptions`. Запроса к модели для расчета этих вариантов нет. Обновление только с хешем разрешается через известное содержимое или запрос полного снимка. Готовность проверяется после распаковки, кеш разделен по клиентам хостов.

Повторяемая проверка на локальном демоне без запуска моделей:

```sh
node tests/providers/live-wire.mjs
```

Проверка использует локальные учетные данные текущего пользователя, сравнивает обычный и сжатый режимы SDK и сохраняет результат в `/tmp/opencode/catalog-live.json`. `HQ_CATALOG_REPORT` меняет путь отчета. Учетные данные в отчет не попадают.

Спинер самого чата не зависит от готовности этого каталога: нативный экран ждет данные агента и синхронизацию истории. Проверка каталога не доказывает устранение задержки этого экрана или переподключений телефона.
