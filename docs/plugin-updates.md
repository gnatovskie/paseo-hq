# Обновление Штаба из настроек

Кнопка «Синхронизировать с репозиторием» запускает `paseo plugin update paseo-hq --yes`
в отдельном процессе Node. Процесс не зависит от старого каталога плагина и продолжает
работать после его остановки при обновлении.

Запрос получает идентификатор операции. Ее состояние и результат команды сохраняются
в `$PASEO_HOME/hq-plugin-updates/<идентификатор>.json` (по умолчанию `~/.paseo`).
Повторный старт с тем же идентификатором читает существующую операцию.
Клиент опрашивает результат, пережидая ошибку остановки плагина. Успех показывается
только после успешного завершения команды. Ошибки команды сохраняются в результате,
автоматического перехода на `git pull` нет.

Команда ограничена тремя минутами, ожидание результата в интерфейсе - четырьмя.
Если плагин не вернулся или процесс завершился без записи результата, интерфейс
сообщает, что итог получить не удалось, и не объявляет обновление успешным.

Проверка: `npm run test:updates`. Тесты запускают настоящий отдельный процесс,
проверяют его результат после выхода инициатора, отказ команды и восстановление
опроса после ошибки `Plugin stopped`.

Живая проверка на хосте установленного Paseo:

```sh
PASEO_PASSWORD_FILE=/путь/к/паролю node tests/plugin-sync/live.mjs
```

Она действительно обновляет установленный Штаб, вызывает клиентский обработчик через
RPC демона и проверяет результат операции и состояние плагина. Для проверки конкретной
поставки задайте `EXPECT_REVISION` полным SHA. Отчет сохраняется в `/tmp/hq-update-live.json`
или по пути `HQ_LIVE_REPORT`. `PASEO_CLIENT_MODULE` позволяет указать модуль клиента из
установки CLI, если он недоступен из текущего каталога.
